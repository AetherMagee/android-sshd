# android-sshd

A Magisk / KernelSU / APatch module with a small SSH server for rooted Android (arm64):

- **Public-key auth**, plain OpenSSH `authorized_keys` format.
- **Per-key privileges**: root, `shell` (same as `adb shell`: uid 2000, its groups and SELinux context) or any uid.
- **Approval on the phone**: after the key checks out, a notification asks **Allow 15 min / Allow 1 h / Deny** (Allow needs the phone unlocked; before Android 12 the prompt is hidden from the lock screen instead). One approval covers that key from that device for the chosen time; no answer within a minute means deny.
- **Max connection age**: connections are closed after a per-key limit (default 8h), even if active, with a warning a minute before.
- **Tailscale-aware**: by default only tailnet peers can connect, prompts name the device (`tailscale whois`), and keys can be pinned to a device. Works with [android-tailscaled](https://github.com/AetherMagee/android-tailscaled).
- **WebUI** (KernelSU / APatch / MMRL): add, edit and remove keys, server settings, logs.

## Install

1. Download the zip from [Releases](https://github.com/AetherMagee/android-sshd/releases/latest) and install it in your root manager. It also installs the small "SSH approvals" app that shows the prompts.
2. Add your public key in the WebUI, or to `/data/adb/sshd/authorized_keys`.
3. `ssh root@<phone>`.

Port 22 on tailnet IPs goes to Tailscale SSH if that's enabled; turn it off (`tailscale set --ssh=false`) or set another `PORT` in `/data/adb/sshd/sshd.conf`.

## Keys

One key per line, optionally prefixed with options:

```
ssh-ed25519 AAAA... me@laptop
user="shell",approve="always",max-age="30m" ssh-ed25519 AAAA... me@work
user="root",approve="never",from-node="backup-box",no-port-forwarding ssh-ed25519 AAAA... backups
```

| Option | |
|---|---|
| `user="root"` | `root` (default), `shell`, or a numeric uid |
| `approve="window"` | prompt, then remember for 15 min / 1 h (default) |
| `approve="always"` | prompt on every connection |
| `approve="never"` | no prompt |
| `max-age="8h"` | close connections after this long (default `8h`) |
| `from-node="laptop"` | only from this tailnet device |
| `no-port-forwarding` | refuse `ssh -L` |

Any other option (e.g. OpenSSH's `command=`) makes the key unusable rather than silently ignored. The login name is ignored: the key decides who you are. Changes apply on the next login.

## Usage

| | |
|---|---|
| `sshd.service {start\|stop\|restart\|status\|log}` | manage the daemon |
| `/data/adb/sshd/sshd.conf` | port, tailnet-only, prompt timeout |
| `/data/adb/sshd/` | keys, settings, host key, log, root's home; kept on uninstall |

Supported: shell (with pty), exec, sftp/scp, local forwarding (`ssh -L`), connection multiplexing (`ControlMaster`). Not supported: remote forwarding (`-R`), agent and X11 forwarding, legacy `scp -O`.

Approval and max-age apply per connection: sessions multiplexed over a `ControlMaster` connection ride its approval and close with it.

## Limitations

- arm64 only.
- sftp as non-root users needs the module's binary mounted into `/system/bin`: after the first reboot, and on KernelSU only with a mounting metamodule.
- Apps with notification access (smartwatch bridges, KDE Connect, ...) can press the notification's buttons, bypassing the unlock requirement. So can anything with shell-uid access (adb, a `user="shell"` session) via `input tap` while the phone is unlocked: approval guards against a stolen key, not against someone already on the phone.
- Approval windows live in memory: restarting the daemon forgets them.
- A numeric `user=` uid keeps the root manager's SELinux context; only `shell` switches context too.
- `user="shell"` is not a hard boundary if your root manager grants `su` to the shell uid (e.g. after allowing it for adb).
- With android-tailscaled in `TUN=userspace-networking` mode, tailnet peers arrive from 127.0.0.1: keep the default kernel TUN mode (tailnet-only mode would reject them).
- `from-node=` matches the device's name (as in `tailscale status`), which tailnet admins can rename; it narrows a key, it doesn't replace it.
- Port forwarding connects from the server process (root), whatever the key's `user=`. Use `no-port-forwarding` on keys that shouldn't reach the phone's network as root.
- Approvals are read from the companion app's private storage. If the app is uninstalled, another app installed under the same package name could answer prompts (it still can't log in without a key).

## Building

```sh
./build.sh
```

Needs Go, a JDK and the Android SDK (build-tools, a platform and the NDK; `$ANDROID_HOME` or `~/Android/Sdk`). Produces `dist/android-sshd-v<VERSION>.zip`. Bump `VERSION` to release; `CHANGELOG.md` and release notes are generated by CI from `feat:`/`fix:` commit subjects since the previous release.
